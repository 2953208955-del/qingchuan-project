# 清川 · 全息大屏前端改版设计

- 日期：2026-10-25
- 状态：待用户确认
- 范围：整个 Web 前端的视觉与信息架构改版；不改后端 API、数据库 schema、Agent 流程与评测口径
- 主设计分辨率：1920×1080（向下兼容 1440/1280，移动端线性降级）

## 1. 意图

现有前端是浅色、卡片式的工具型界面，能证明流程正确，但不能在省赛视频与答辩大屏上传达“智慧水利 + 多模态巡检 Agent”的产品气质。

本次把整个产品统一为深空青全息视觉系统。首页从产品介绍页改成指挥大屏；巡检、报告、知识库、评测保留全部功能与真实数据，只更换信息呈现与视觉语言。目标不是做一张静态概念图，而是让评委在 5–8 分钟视频里看到一套可点击、数据真实、视觉统一的系统。

## 2. 用户已确认的决定

1. **整体改**：不是新增一个演示页，而是全产品统一切换到深色全息风格。
2. **用现有数据**：不伪造识别结果、指标或评测数字。
3. **首页替换**：`/` 直接变成指挥大屏，覆盖现在的主页介绍内容。
4. **地图口径**：聚焦最新一条含识别结果的任务（当前为 `demo-run-001`，3 图 / 8 目标 / 2 个待复核点）；库中没有经纬度，河道与点位按示意排布并明确标注。
5. **视频口径**：右侧窗口轮播该任务的真实巡检原图，明确标为“巡检影像回放”，不伪装成实时视频流。
6. **看板口径**：指标用全库真实累计；点击地图光球展示真实类别、置信度、复核状态与原图缩略图。
7. **其余页面**：保留现有流程与功能，统一换肤；报告打印版保持浅色可读。

## 3. 目标、非目标与反目标

### 目标

- 1920×1080 下，大屏首屏完整呈现：悬浮标题栏、左侧树状导航、中心河道态势图、右侧影像与数据看板。
- 所有页面共享同一套全息设计语言，而不是只有首页好看。
- 地图点位、视频帧、图表和数字全部由本地 SQLite 真实数据驱动。
- 保留巡检、复核、重新生成、导出、知识检索、评测展示的全部既有行为。
- 动效克制、可关闭，信息层级清楚；不靠堆砌发光来制造科技感。
- 通过现有单元测试、E2E、typecheck、lint、build，并新增大屏数据与交互测试。

### 非目标

- 不接真实 GIS 底图、GPS 轨迹或实时视频流。
- 不引入 Three.js/WebGL、地图 SDK、新字体包或新图表库。
- 不新增后端接口，不改数据库结构，不改 Agent 与评测结果。
- 不把演示数据包装成实时 AI 输出或评测结论。
- 不合并分支、不推送、不打提交 tag。

### 反目标

- 卡通化、游戏 HUD 化、满屏跑马灯。
- 厚重实体边框、深色不透底卡片、堆叠纹理。
- 为了视觉效果虚构数字、坐标、告警或“实时在线”状态。
- 改版后报告打印不可读，或巡检/复核流程被视觉层遮断。
- 只适配 1920，普通笔记本直接溢出或无法操作。

## 4. 数据真实性与口径

### 4.1 首页主任务

服务端按 `createdAt` 倒序选择“最新一条同时拥有已分析图片和识别结果的任务”作为主任务。当前即 `demo-run-001`。它已有 3 张真实照片、8 条识别、2 条低置信待复核，是最适合讲清“识别 → 复核 → 报告”闭环的样本。

主任务区域显示：

- 任务地点（`示例河段 A 段`）、任务状态、创建时间。
- 演示来源按该任务最新报告的 `contentJson.source === 'manual'` 判定，显示轻量标注“演示任务 · 人工构造数据”。任务没有报告时不做来源断言，也不显示演示标记。
- “查看完整报告”仅在该任务存在报告时出现；否则显示“报告尚未生成”，避免 404 死链。
- 地图图例写明“河道与点位为示意排布，点位内容来自真实识别结果”。

没有符合条件的主任务时，地图展示全息河道骨架与空状态文案，不生成假点位。

### 4.2 数据看板

右侧看板使用全库真实聚合：

- 统计范围统一为 `reviewStatus !== 'rejected'` 的识别结果；`natural` 保留在识别统计中，但用中性色标注“自然漂浮物 · 不计入污染强度”。被拒绝的识别不进入任何数字、图表、点位或回放框。
- 累计巡检任务数（`runs`）。
- 累计识别目标数（上述范围内的 `detections`）。
- 低置信待复核数：只统计 `reviewStatus === 'pending' && confidence < 0.5`，不把普通 pending 误报为“待复核”。
- 平均置信度：上述统计范围内的算术平均，保留一位小数或百分比整数展示。
- 报告数（`reports` 按 run 去重后的最新版本数）；放在地图底栏摘要与看板标题行，不额外占用 KPI 格。
- 识别类别构成环形图：最多 5 个具名扇区 + “其余类别”聚合扇区；图例与无障碍摘要列出全部类别的真实计数。
- 置信度分布折线图（0–0.2 / 0.2–0.4 / 0.4–0.6 / 0.6–0.8 / 0.8–1.0 五档）。

所有数字在服务端计算后直接渲染。客户端只做进出场与计数动画，不在浏览器重算业务指标。

### 4.3 地图点位

主任务中每条未拒绝的识别结果对应一个光球：

- 普通点：湖蓝/青色脉冲。
- `natural`：低饱和青灰点，图例标“自然漂浮物”。
- `pending` 且 `confidence < 0.5`：淡洋红脉冲，图例标“待复核”。
- 点位位置从固定示意锚点序列按识别顺序分配，并加确定性的微小偏移，避免重叠；不声称是地理位置。
- 点位超过 24 个时，展示置信度最高的 24 个并在图例标注“展示 24/总数”，不静默截断。

点击/键盘激活光球弹出半透明信息层：类别中文名、置信度、复核状态、来源图片缩略图、任务 ID，以及“查看完整报告”链接（任务无报告时显示“报告尚未生成”）。点击空白或按 Esc 关闭，焦点返回光球。

### 4.4 影像窗口

- 轮播主任务中状态为 `analyzed` 的真实原图。
- 标注“巡检影像回放 · 非实时”和帧序号。
- 清晰图按原始比例居中显示，不放大低分辨率图；底层用同图模糊铺满，避免留白。识别框叠在与清晰图完全同尺寸的包裹层上，不用 `object-cover` 裁剪后直接覆盖，避免框错位。
- 不伪造拍摄时间码：只显示任务创建时间（标注“任务创建”）与“帧 1/3”，不显示走动的“实时”时钟。
- 叠加深青扫描框与当前帧未拒绝的真实识别框；待复核框为洋红。
- 自动轮播间隔 6 秒；悬停、聚焦或 `prefers-reduced-motion` 时暂停。
- 无图片时展示全息扫描占位，不伪造航拍画面。

## 5. 视觉系统

### 5.1 色彩

| 角色 | 颜色 | 用途 |
|---|---|---|
| 深空底 | `#041419` / `#061C22` | 全局背景、最深层次 |
| 湖蓝主光 | `#74E6F2` | 河岸线、主数据、焦点 |
| 远湖蓝 | `#5AA7FF` | 次级轮廓、图表第二色 |
| 淡鎏金 | `#D8BE82` | 航线、关键数字、细节描边 |
| 淡洋红 | `#FF86B7` | 仅用于待复核/告警脉冲 |
| 主文字 | `#E6F6F7` | 标题与正文 |
| 次文字 | `#8FB2B8` | 标签、说明 |
| 分隔线 | `rgba(116,230,242,.16)` | 面板边界 |

洋红是告警专用色，不参与普通图表系列，避免告警语义失效。普通类别使用青、蓝、金、青绿、浅雾白五个色相。

原 shadcn 语义 token 保留并整体改为深色映射，避免现有组件出现浅色残留。`color-scheme: dark`。

### 5.2 字体与数字

- 西文/数字：现有 Geist；中文：`PingFang SC` / `Microsoft YaHei Light` / `Microsoft YaHei`。
- 标题使用 300–400 字重、略宽字距；正文 400。
- KPI 使用等宽数字（`tabular-nums`）+ Geist Mono，字号 28–44。
- 小标签使用 10–11px、大写字距；不使用全大写中文。
- 发光弱描边：`text-shadow: 0 0 16px rgba(116,230,242,.28)`，只用于标题与关键数字。

### 5.3 面板与层次

统一 `.holo-panel`：

- 背景：深青渐变 + 8–14% 白色雾面，`backdrop-filter: blur(20px) saturate(120%)`。
- 边界：1px 半透明青色线；四角短 L 形高光，不使用完整粗边框。
- 阴影：外侧大范围低透明体积光 + 内侧 1px 高光，形成悬浮感。
- 圆角：18–22px；内部卡片 12–14px。
- 标题行：细线分隔，标题左侧 2px 青金短标；操作区靠右。
- 双层质感：毛玻璃底 + SVG/线框内容；不叠杂乱纹理。

### 5.4 背景氛围

`HoloBackdrop` 固定层，`aria-hidden`、`pointer-events-none`：

1. 深空青基底与两团低透明径向光（青 + 极淡金）。
2. 两层缓慢漂移的河面波纹 SVG，模糊、低对比。
3. 16–24 个确定性水粒子光晕，CSS 动画缓慢上浮。
4. 细扫描线 + 约 12 秒一次的极淡纵向扫光。
5. 底部轻微透视网格与暗角，远处河道轮廓用高斯模糊虚化。

全部 CSS/SVG，无外部贴图。动效在 `prefers-reduced-motion` 下停止。

### 5.5 动效

- 标题：每 8 秒一次低亮扫光掠过文字，不做持续闪烁。
- 航线：金色虚线缓慢流动，周期 9–14 秒。
- 光球：2.4 秒呼吸脉冲；待复核点洋红，节奏略快。
- 数据：数字 700ms 计数；图表入场 600ms；不做无限抖动。
- 页面切换：仅面板淡入 + 6px 上移。
- 所有动画使用 transform/opacity，避免布局抖动。

## 6. 全局框架

### 6.1 布局

- 背景层固定。
- 左侧悬浮树状导航：宽 236px，距边缘 20px，圆角 22px，独立浮空。
- 顶部悬浮标题栏：高约 72px，横跨内容区，毛玻璃 + 扫光标题。
- 内容区：左侧留出导航宽度 + 间距。
- 1920 下主内容可用宽度约 1600px；总览页铺满，其他页面最大 1500–1600px。
- 1024–1439：导航收窄到 200px，右栏由 400 收至 340。
- <1024：导航变为顶部横向滚动节点；总览按“地图 → 影像 → 看板”纵向排列。

### 6.2 导航

树状分组，节点带图标与轻微悬停位移：

- 总览：总览大屏 `/`
- 巡检作业：巡检工作台 `/inspect`、报告库 `/reports`
- 知识中枢：知识库 `/knowledge`、评测中心 `/eval`

当前路由节点用左侧光条 + 背景微光标记。品牌“清川”仍链接 `/`，保留原无障碍名称。打印时隐藏。

### 6.3 顶栏

左侧品牌与系统副标题，中间系统名“河湖垃圾智能巡检系统”，右侧“系统在线”状态点、本地时间、演示环境标签。仅“演示环境”为静态标签，不伪造服务器在线探针；“系统在线”可改为中性的“本地运行”文案，避免误导。

## 7. 首页指挥大屏

### 7.1 桌面布局

- 主网格：`minmax(0,1fr) 400px`，间距 20px。
- 中央：河道态势面板占满高度。
- 右栏：上方影像窗口约 42%，下方数据看板约 58%。
- 页面高度：`calc(100vh - 顶栏 - 外边距)`，1080 下不出现整页滚动；更矮屏幕允许滚动。
- 地图底部内嵌图例与任务摘要条，显示“累计任务 5 · 报告 4 · 标准条款 6”；报告数落在这里，不额外占用 KPI 格。

### 7.2 河道态势图

- 单张响应式 SVG，viewBox 约 `1200×760`。
- 5–7 层深度：远景虚化河道 → 地形等高线 → 主河道水带 → 河岸发光轮廓 → 水面反射 → 航线 → 点位。
- 主河道从左上贯穿右下，河岸用青色渐变细线勾边，内部用低透明湖蓝填充。
- 航线为金色三次贝塞尔路径，虚线流动，节点有微弱光晕。
- 等高线、网格与上下游标签只作低透明背景信息。
- 右上角显示“河段态势 · 示意”，左下角图例说明点位来源。
- 地图容器不实际旋转 3D，而用分层错位、透视网格、阴影与高差光营造 2.5D；避免文字与点击区域随变换错位。

### 7.3 数据看板

- 第一行 2×2 KPI：累计识别、待复核、平均置信度、巡检任务。
- 第二行环形图：识别类别构成，中心显示总数；最多 5 个具名扇区，其余聚合为“其余类别”，图例与无障碍摘要保留全部真实计数。
- 第三行折线图：置信度分布，线框风格，仅细网格与端点光点。
- 所有图表有文字摘要作为无障碍替代，不只依赖颜色。
- 图表用内联 SVG 绘制（环形与折线），不用 `recharts`：全息线框、渐变、端点光晕和固定比例更好控制，也避免 ResizeObserver/水合问题。服务端传入已聚合数据。

### 7.4 影像窗口

- 16:10 左右，真实图片 `object-cover`，低分辨率图用同图模糊铺底避免大片留白。
- 四角扫描框、顶部“巡检影像回放 · 非实时”、底部文件名/地点/任务号。
- 当前帧的真实识别框以细青线叠加；待复核框为洋红。
- 轮播指示点与上一帧/下一帧按钮可键盘操作。

## 8. 其余页面换肤

### 8.1 巡检工作台 `/inspect`

- 改为两栏工作区：左侧“任务输入 + 计划 + 证据画布”，右侧“执行时间线 + 识别结果 + 复核 + 标准条款”。
- 上传区变成全息投递框，保留 `aria-label="上传图片"`、文件输入、进度和错误文案。
- 所有按钮、输入、下拉统一全息样式；保留既有可访问名称与测试定位文本。
- 不改变上传、计划、开始、SSE、复核和重新拉取的任何逻辑。
- 移动端恢复单列，顺序与桌面一致。

### 8.2 报告库 `/reports`

- 报告条目改为悬浮行卡：标题、状态徽标、严重度、污染强度、时间、进入箭头。
- 状态颜色：草稿青、待复核洋红、过期金/红；不能只靠颜色，保留文字。
- 空状态带全息线框插画与“去巡检”入口。

### 8.3 报告详情 `/reports/[id]`

- 报告正文放在宽幅全息文档面板内，保留现有 claims、指标、证据联动、复核、重新生成与导出。
- 指标摘要改为细线数据栏；严重度用低饱和色块。
- 证据画布识别框保持可点击；选中与引用高亮改成青/金双色，不改变 store 逻辑。
- 复核区使用洋红提示，但操作按钮仍清晰可辨。

### 8.4 知识库 `/knowledge`

- 顶部为命令式检索条；结果条款为线框卡，显示标准号、条款号、得分。
- 保留“未找到依据”、检索中、错误等状态。

### 8.5 评测 `/eval`

- 三组评测改为指标面板：检测 P/R/F1、RAG Recall@5、Agent 成功率与平均耗时。
- 保留 dry-run 警告、生成时间、未运行时的命令列表与数据来源。
- 不重新计算或美化数字；原值原样显示。

### 8.6 打印 `/reports/[id]/print` 与报告打印

- 屏幕仍是全息风格；`@media print` 强制白底黑字、隐藏背景/导航/顶栏/光效/按钮。
- 面板退化为 1px 灰边框、无阴影、无背景图；分页与正文可读。
- 既有“待复核不可打印”的打印提示与原逻辑不变。

## 9. 技术架构

### 9.1 新增结构

```text
src/components/holo/
  holo-backdrop.tsx        // 固定背景氛围
  holo-panel.tsx           // 面板外壳 + 角标 + 标题行
  holo-badge.tsx           // 状态/来源标签
  holo-count-up.tsx        // 数字计数（reduced-motion 安全）

src/components/dashboard/
  dashboard-hero.tsx       // 首页网格装配（服务端）
  river-map.tsx            // 地图 SVG + 点位 + 弹窗（客户端）
  image-replay.tsx         // 影像轮播（客户端）
  stats-board.tsx          // KPI + 环形图 + 折线图（服务端 SVG + 计数客户端岛）

src/lib/dashboard/
  overview.ts              // DB 读取与纯聚合
  types.ts                 // 可序列化视图模型
```

### 9.2 数据流

`src/app/page.tsx`（服务端，`force-dynamic`）→ `loadDashboardOverview()` 读取 SQLite → 生成纯数据视图模型 → 传给客户端地图、轮播和图表。客户端不发额外请求获取大屏数据。

地图点位坐标与置信度分档由纯函数生成，独立单测，不依赖 DOM。

### 9.3 样式

- 设计 token、关键帧、`.holo-*` 基础类集中在 `globals.css`。
- 现有 shadcn token 全部映射为深色，组件不需要逐个例外。
- 不新增依赖；图标用现有 `lucide-react`，图表用内联 SVG，动效优先 CSS。
- 大屏影像与地图缩略图来源为 `/api/images/[id]`。缩略图用 `next/image`；轮播主图需要按原始比例自适应，使用原生 `<img>` 并在该处局部禁用 `@next/next/no-img-element`，以保证识别框与图片同尺寸包裹层。

### 9.4 既有组件

- `AppShell` 重写为背景 + 树状导航 + 顶栏 + 内容区；仍包裹全部路由。
- `SiteNav` 保留导出名，内部改树状导航；新增“总览大屏”节点并标记当前路由。

## 10. 无障碍、动效与性能

- 所有图标按钮有 `aria-label`；地图光球是真实 `<button>`，支持 Tab/Enter/Space。
- 弹窗 `role="dialog"`，打开后聚焦弹窗，Esc 关闭并归还焦点。
- 焦点环使用青色 2px 外扩，任何毛玻璃面板上均可见。
- 文本对比度按 WCAG AA 检查；洋红只用于小面积告警与文字标签。
- 图表提供可见文字摘要；颜色不是唯一编码。
- `prefers-reduced-motion: reduce`：停止背景漂移、扫光、航线流动、脉冲、计数与自动轮播。
- 背景粒子 ≤24 个，全部 transform/opacity；无 WebGL、无地图 SDK、无大图纹理。
- 图表与轮播为客户端小岛，服务端大屏数据零客户端请求。
- 低端设备可用：`backdrop-filter` 不支持时回退为半透明纯色。

## 12. 由构建者决定的事项

以下不是用户承诺，是本设计的执行选择，用户可在审阅时推翻：

1. 用 SVG + CSS 2.5D，不引入 Three.js/WebGL。
2. 主设计分辨率 1920×1080，1920 以下线性降级。
3. 首页主任务按“最新且含识别结果”自动选择，当前落到 `demo-run-001`。
4. 看板 KPI 采用累计识别、低置信待复核、平均置信度、巡检任务四项。
5. 影像窗口明确标注回放，不做假实时。
6. 打印保持浅色。
7. 不新增依赖，图表改用内联 SVG（不用 `recharts`）。
8. 地图展示上限 24 个点位；超出时在文案中明示。
9. 所有统计排除 `rejected`；`natural` 保留但用中性色标注，不计入污染强度。
10. “演示任务”由最新报告 `source === 'manual'` 推导，不硬编码 run id；无报告不显示该标记。
11. 影像清晰图按原始比例居中，识别框只叠在同尺寸包裹层上，避免裁剪错位。
12. 环形图最多显示 5 个具名扇区，其余聚合；完整类别计数保留在图例与无障碍摘要中。
13. 任务没有报告时，地图弹窗隐藏报告链接，显示“报告尚未生成”。

## 13. 风险与对策

| 风险 | 对策 |
|---|---|
| SVG 无真 3D，深度感不足 | 多层错位、透视网格、体积光、模糊远景叠加；先保证信息与交互 |
| 演示照片 `sample-3` 分辨率低 | 模糊同图铺底 + 原尺寸居中显示，不拉伸放大成主视觉 |
| 原图裁剪导致识别框错位 | 清晰图按原始比例显示，框与图共用同尺寸包裹层，不做 `object-cover` 覆盖 |
| 深色毛玻璃影响正文可读性 | 正文面板提高不透明度，发光只放在边缘/标题；打印强制白底 |
| 图表与大量光效拖慢低端机 | 客户端小岛、固定高度、transform/opacity、粒子上限、reduced-motion |
| 全站换肤破坏既有测试 | 保留 aria-label、按钮名和关键文案；导航测试只显式更新新增节点 |
| 数据为空时大屏“破相” | 专门设计空状态：河道骨架仍在，点位/影像/图表显示真实空文案 |
| 误把示意当真实 GIS | 地图、航线、演示任务三处标注“示意/回放/演示” |
